# Extracting a published model into inflect-models-db

Turn a paper's mathematical model into a curated, **validated** entry: an
Antimony model file plus a `card.yaml` whose targets assert that the model, run
through `viva-tellurium`, reproduces the results the paper reports.

The end state is: `inflect_models_db/models/<slug>/` exists, `pytest -k <slug>` is green,
`figures/` holds a reproduction a reviewer can compare to the paper, and
`inflect-models grade <slug>` is OK — the structured reading of the paper
(`extraction.yaml`) reconciles with the Antimony you wrote.

The pipeline is staged, and each stage leaves an auditable artifact:

```
paper ──▶ extraction.yaml ──▶ model.ant ──▶ card.yaml ──▶ validate + grade (repair loop)
          (structured          (faithful     (published      (numbers reproduced +
           reading)             Antimony)     targets)         structure reconciled)
```

Author `extraction.yaml` **before** `model.ant`: it is the reviewable record of
how you read the model out of the paper, and the grade checks the Antimony
against it. Do not skip straight to Antimony.

## Preconditions

- An environment where `import inflect_models_db` works and `viva-tellurium` is
  installed (see the repo README — `uv pip install -e .`).
- The source paper (equations + at least one quantitative figure or table).

## Workflow — do these in order

### 1. Create the model folder

Pick a slug: `<firstauthor>-<year>-<short-topic>` (e.g.
`reynolds-2006-acute-inflammation`). Create:

```
inflect_models_db/models/<slug>/
  extraction.yaml  # the structured reading of the paper (author this first)
  paper/        # CITATION.md always; the PDF only if its licence permits (see §7)
  reference/    # digitized/transcribed published numbers
  figures/      # generated by validation — do not hand-draw
```

### 2. Read the model out of the paper — into `extraction.yaml`

Read the model out of the paper and record it, structured, in
`extraction.yaml` (schema: `docs/extraction-schema.md`). This is the stage a
reviewer can check against the paper *before* any Antimony exists. Capture, each
with a pointer to where in the paper it came from:

- **`state_variables`** — id, meaning, units.
- **`equations`** — one right-hand side per state variable, every term, with its
  source (equation number / section).
- **`parameters`** — every parameter, published value + units + `source` (table /
  page). The grade fails if any parameter is uncited.
- **`initial_conditions`** — per state, with a source.
- **`targets`** — the published results you will assert in `card.yaml`, each cited.

Every parameter and target **must** carry a `source`; that is what makes the
extraction auditable and what the fidelity grade checks. See the Reynolds 2006
`extraction.yaml` for a worked example.

If the model is deposited in **BioModels**, fetch the curated SBML as a
cross-check (not a substitute for reading the paper):

```bash
curl -sL "https://www.ebi.ac.uk/biomodels/model/download/<BIOMDxxxx>?filename=<file>.xml" -o /tmp/ref.xml
python -c "import tellurium as te; print(te.sbmlToAntimony(open('/tmp/ref.xml').read()))"
```

Confirm the curated parameters match the paper. If they diverge, trust the paper
and note the discrepancy in the card's `model.provenance`.

### 3. Author `model.ant` from the extraction

Translate the `extraction.yaml` into faithful Antimony — one species per
`state_variable`, one rate rule per `equation`, every `parameter` declared with
its published value. The grade later checks they line up, so keeping the
Antimony in step with the extraction here saves a repair cycle.

Prefer **rate-rule form** (`X' = ...`) when the paper
presents ODEs — it reads line-for-line against the paper. Declare the state
variables as `species` so libroadrunner exposes them as floating species:

```antimony
model <slug_identifier>
  species P, Nstar, D, C_A;
  aux := ...;            // assignment rules for repeated sub-expressions
  P' = ...;              // one rate rule per state variable
  P = 1; Nstar = 0; ...  // initial conditions (baseline; scenarios override these)
  k_pg = 0.3; ...        // every parameter, published values
end
```

Keep a header comment citing the paper. Reaction form is also fine when the
paper is written as a reaction network.

### 4. Choose validation targets from the paper's results

Pick what the paper actually claims and that this model can reproduce
deterministically — steady states, thresholds/bifurcations, oscillation period,
a characteristic trajectory. For each **scenario** record the initial conditions
and the expected steady-state value + tolerance per watched variable. If the
paper shows a **threshold** (a control value separating qualitatively different
outcomes), encode it too.

Transcribe the reference numbers into `reference/*.csv` with a comment saying
where in the paper they come from (figure/table). Set tolerances to a few
percent of the value, loose enough for integrator differences, tight enough to
be meaningful.

**Make the validation strong — add these to the card when you can:**

- `steady_state: {rel_change_below: 1.0e-3}` — a convergence guard so the
  endpoint targets can't be read mid-transient. Add it for every model.
- `oracle: {kind: sbml, file: reference/<id>.xml, nrmse_below: 1.0e-3}` — if the
  model is deposited in BioModels (CC0) or ships a reference SBML, commit it to
  `reference/` and declare it. Validation simulates that encoding independently
  and checks the full trajectory, not just endpoints — the strongest automatic
  check available.
- a `threshold` block whenever the paper reports a qualitative boundary.

### 5. Write `card.yaml`

Follow `docs/model-card-schema.md`. Minimum: `slug`, `source` (with a
doi/pubmed/biomodels id), `model` (file/format/species), and `validation` (time,
scenarios, optional threshold, figures).

### 6. Validate, grade, and iterate — the repair loop

Two independent checks must both pass: **validation** (does the model reproduce
the published *numbers*) and the **fidelity grade** (does the Antimony
faithfully encode the *paper*, reconciled against `extraction.yaml`).

```bash
python -m inflect_models_db.cli validate <slug>     # prints PASS/FAIL per target
python -m inflect_models_db.cli grade <slug>        # structural fidelity vs extraction.yaml
python -m inflect_models_db.cli reproduce <slug>    # writes figures/<name>.png
pytest -k <slug> -q
```

Run the **bounded repair loop** until both are green (give up honestly after a
few iterations rather than fudging):

1. `validate` → if a target fails, the bug is almost always a mistyped
   parameter, a wrong initial condition, or a units/time-scale mismatch. Fix the
   **Antimony** or the **target** — never widen a tolerance to hide a real
   divergence; report the divergence instead.
2. `grade` → a failing component tells you exactly what diverged:
   - *param-coverage* — a parameter is in the model but not `extraction.yaml`
     (or vice versa): you transcribed one the paper doesn't have, or missed one.
   - *state-coverage* — a species has no equation, or the model has a species you
     never declared.
   - *param/initials/target-citation* — add the missing `source:` to
     `extraction.yaml`.
   Fix whichever side is wrong — usually the extraction and the Antimony drifted
   apart and one of them is the mistake.
3. Re-run both. Repeat.

Open the generated figure and compare it to the paper's. The loop ends when
`validate`, `grade`, and `pytest -k <slug>` are all green — or, if you cannot
make the numbers reproduce, when you have documented *why* in the model README
(do not ship a green test over a model you know is wrong).

The optional LLM reviewer (`grade --llm`, needs `INFLECT_LLM_REVIEW_CMD`) adds a
1–5 faithfulness score but is **non-gating** — it never blocks a model and never
substitutes for the numeric validation.

### 7. Write the model README and commit

Render a short model card (`inflect_models_db/models/<slug>/README.md`): state table, equations,
the published result reproduced, the figure, and how to validate. Then commit.

**PDF / copyright:** only commit the paper PDF if its licence allows
redistribution (open access / CC). Otherwise commit `paper/CITATION.md` with the
DOI and leave the PDF git-ignored. The repo `.gitignore` ignores
`inflect_models_db/models/**/paper/*.pdf` by default.

## Red flags — STOP

- *"I'll just download the BioModels SBML and call it extracted."* — The point is
  extraction from the **paper**; BioModels is a cross-check. (Downloading a
  curated SBML to seed the Antimony is fine, but read the paper and keep the
  provenance honest.)
- *"The run is close-ish, I'll loosen the tolerance."* — No. A failing target
  means the model or the target is wrong. Find out which.
- *"Validation is just that it runs."* — Running is necessary, not sufficient.
  The card must assert *published numbers*, and the test must check them.
- *"I'll write the Antimony first and backfill extraction.yaml to match."* — No.
  The extraction is the *reading of the paper*; writing it from the Antimony you
  already wrote makes it a rubber stamp, not a check. Author it from the paper,
  first.
- *"The numbers reproduce, so the grade doesn't matter."* — The grade catches a
  model that hits the targets with the wrong mechanism (a parameter transcribed
  wrong but masked by the fit). Both checks, independently.
